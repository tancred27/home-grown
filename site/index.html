How it works

A collector keeps a record of every component. An answerer searches that record as the person asking, so each person sees only what they may see.

01

Watches your repositories

When someone pushes to a repository, HomeGrown rereads only the folders that changed. A webhook or a poller tells it what moved.

The poller lists an organization's repositories, most recently pushed first, a hundred per request.
02

Records each component

What it's for, what its tests show, who built it and how ready it is. Every note points back to the file it came from.

dskit: prod, 224 facts on record.
03

Answers, or says nothing fits

It finds likely matches and checks each one against your question. If nothing fits, it says so instead of guessing.

Your coding agent checks first

HomeGrown is an MCP server. Claude Code, Cursor and other agents that speak MCP can ask it before they write new code. Each answer says whether you can read the code. If you can't, the agent tells you who to ask instead of writing a copy.

Add it to Claude Code
claude mcp add homegrown -e HOMEGROWN_USER=alice -- python -m homegrown.mcp_server

Reads GitHub repositories, and Confluence and Notion pages. Stores everything in PostgreSQL. Bring Anthropic, Groq, Gemini, or a local model through Ollama, or run with no model at all.

Not there yet

  • No company runs it in production yet.
  • Accuracy drops as the company grows, mostly because of look-alike projects from other teams.
  • No single sign-on, and code access isn't synced from GitHub yet.
  • With a model on, each question costs two model calls, and nothing is cached between questions.

Questions

Does our code leave our network?

Only if you choose a hosted model. Search and embeddings run on your machines, and with a local model through Ollama nothing leaves them.

What does it cost?

Nothing. It's Apache-2.0. A hosted model adds two calls per question.

Does it need a model at all?

No. Without one it answers from what it has found, and says "possibly" instead of "yes".

Where can it read from?

GitHub repositories, plus Confluence and Notion pages. GitLab and Bitbucket are planned.

How does it know what's in production?

From releases and from use: a library that two other teams depend on counts. Until an owner confirms it, a stage is shown as inferred.

Could someone see what they shouldn't?

The database checks every query. Tests run every test user through real searches and fail if anything outside their access comes back.
