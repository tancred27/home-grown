How it works

It keeps a record of every component, and every search runs as the person asking.

  1. 01

    Watches repos

    Rereads only the folders a push changed.

  2. 02

    Reads the code

    Splits a big repo into the parts people reuse.

    kind → CLI, cluster library, kindnetd, Go utilities
  3. 03

    Records it

    Purpose, owner, stage. Every note links to its file or commit.

  4. 04

    Searches, then checks

    Keywords and meaning, then a judge reads the top 20 and picks up to three, each with a reason. If the request is ambiguous, it asks back.

    Which cloud is the storage account in?
  5. 05

    Shows its work

    Why each answer came back: matches, ranks, the judge's reason.

    homegrown explain <id>

Not there yet

  • No company runs it in production yet. There's no single sign-on and no permission sync.
  • Who to ask needs your directory as an import file; there's no SCIM, Okta or Entra connector yet.
  • Accuracy drops as a company grows, mostly from look-alike projects.
  • The code reader and the duplicates job are off by default and not yet run on a real company's code.

Questions

Does our code leave our network?

Only if you choose a hosted model. Search runs on your machines. With the code reader on, short extracts (declarations and their comments, with keys, passwords and internal hostnames removed) go to the model you pick. With a local model through Ollama nothing leaves.

What does it cost?

Nothing: it's Apache-2.0. A hosted model adds two calls per question, and the code reader a cheap call per changed part of the code. Bring your own key (Anthropic, Gemini, Groq or Ollama), or run with no model at all.

Where can it read from?

GitHub repositories, including their source code if you turn that on, plus Confluence and Notion pages. GitLab and Bitbucket are planned.

Who does it tell me to ask?

The two people who committed to it most recently and are still in your company directory, with their manager. If no one fits, the owning team's lead.

Does it need our directory?

Only for who to ask. You import a snapshot: id, name, team, manager, line of business and whether someone is active. Emails and logins are kept only as hashes, and nothing else is stored.

How does it know what's in production?

From releases and from use: a library two other teams depend on counts. Until an owner confirms it, a stage is shown as inferred.

Could someone see what they shouldn't?

The database checks every query. Tests run every test user through real searches and fail if anything outside their access comes back.
